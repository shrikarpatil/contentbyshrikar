# Automated Faceless YouTube + Instagram — 30-Day Experiment

## Objective

Build a lightweight AI-powered content pipeline that automatically researches topics, generates screenplays, creates videos, and publishes them to YouTube and Instagram.

The goal is **not** to build a production-grade system or a resume project.

The goal is to answer one question:

> **Can an automated faceless-content pipeline consistently produce videos that attract enough views and engagement to become a viable side-income stream?**

Run the experiment for **30 days** and use the results to decide whether to continue, modify, or scale it.

# 2. Content Production Frequency

Start with:

**1 video/day**

After the pipeline becomes reliable, increase to:

**2 videos/day**

The first objective is not maximum volume.

The objective is to establish whether the pipeline can produce **watchable content consistently**.

### 30-Day Target

Approximately:

* Minimum: 30 videos
* Maximum: 60 videos

---

# 3. Agent Architecture

## Agent 1 — Topic Generator

### Purpose

Identify interesting and potentially high-performing topics.

### Tools

* Web search
* Trending-topic research

### Input

No input or optional content-niche configuration.

### Responsibilities

1. Search for current/trending topics.
2. Identify topics with strong audience interest.
3. Look for unusual angles rather than simply repeating news headlines.
4. Consider whether the topic can be converted into an engaging short-form video.
5. Select a content angle.

### Output

The agent should produce a structured **content opportunity**.

Example:

```json
{
  "topic": "...",
  "why_now": "...",
  "target_audience": "...",
  "content_angle": "...",
  "hook_idea": "...",
  "format": "short",
  "estimated_interest": "high"
}
```

### Important Principle

Do not ask:

> "Give me a trending topic."

Ask:

> **"Find a content opportunity worth making a video about."**

---

# 4. Agent 2 — Topic Researcher

## Purpose

Research the selected topic and provide reliable information to the screenplay generator.

### Tools

* Web search

### Input

The content opportunity generated by the Topic Generator.

### Responsibilities

* Research the topic.
* Verify important claims.
* Find relevant facts.
* Find interesting statistics.
* Identify useful context.
* Identify contradictions or caveats.
* Find primary or authoritative sources where possible.
* Collect useful URLs.

### Output

```text
Topic
Why it matters
Key facts
Important context
Interesting statistics
Interesting details
Contradictions / caveats
Sources
URLs
```

### Important Principle

The Researcher is primarily a **fact-finding agent**, not a creative writing agent.

The Script Generator should use the research output rather than independently inventing facts.

---

# 5. Agent 3 — Script Generator

## Purpose

Convert the research into a highly engaging short-form video screenplay.

### Tools

None.

### Input

* Content opportunity
* Research output

### Output

A detailed screenplay that can be directly passed to the video generation model.

---

## Screenplay Structure

The screenplay should not be just narration.

It should contain instructions for the entire video.

Example:

```text
TITLE:
...

TOTAL DURATION:
...

SCENE 1
Duration: 0–4 seconds

VISUAL:
...

VOICEOVER:
...

ON-SCREEN TEXT:
...

SFX:
...

TRANSITION:
...


SCENE 2
Duration: 4–9 seconds

VISUAL:
...

VOICEOVER:
...

ON-SCREEN TEXT:
...

SFX:
...

TRANSITION:
...
```

# 6. Content Creation Principles

The Script Generator should consistently apply principles such as:

### Hook

The first few seconds must create a reason to keep watching.

Possible approaches:

* Curiosity
* Surprising fact
* Contrarian statement
* Question
* Unexpected outcome
* Strong claim
* Story beginning in the middle

### Pacing

Avoid unnecessary introductions.

Bad:

> "Hey guys, welcome back to the channel..."

Prefer immediately entering the story.

### Information Density

Every scene should contribute something.

Avoid:

* Repetition
* Filler
* Generic statements
* Long introductions

### Curiosity Loops

Where appropriate, introduce unanswered questions that are resolved later.

### Payoff

The video should deliver on the promise made by the hook.

### Visual Variety

The screenplay should specify changing visuals rather than keeping one static visual throughout the video.

### Ending

Where appropriate:

* Strong conclusion
* Interesting final fact
* Open loop
* Question
* Natural CTA

---

# 7. Agent 4 — Reviewer

## Status

**Optional for the first version.**

The primary purpose of this agent is not safety.

LLMs already have safety guardrails.

The reviewer is useful for **content quality control**.

### Possible Evaluation

Score the screenplay on:

```text
Hook                /10
Curiosity           /10
Story progression   /10
Pacing              /10
Originality         /10
Clarity             /10
Payoff              /10
Shareability        /10
```

### Decision

```text
Score >= threshold
        ↓
Generate Video

Score < threshold
        ↓
Regenerate Screenplay
```

If the reviewer adds too much complexity or cost, remove it initially.

---

# 8. Video Generation

## Input

The detailed screenplay.

## Output

A finished short-form video.

The video generator should ideally handle:

* Visual generation
* Voiceover
* Scene transitions
* Background music
* Sound effects
* Captions
* Timing
* Aspect ratio

### Primary Goal

Create a video that feels like actual short-form content rather than:

> AI voice + random stock footage.

The screenplay should therefore contain enough visual direction for the video model to understand what should appear in every scene.

# 9. Publishing

After video generation:

```text
Generated Video
      │
      ├───────────────► YouTube Shorts
      │
      └───────────────► Instagram Reels
```

The publishing layer should automatically provide:

### YouTube

* Video
* Title
* Description
* Tags/metadata where appropriate

### Instagram

* Video
* Caption
* Hashtags where appropriate

The system should store the published video/platform identifiers so performance can be associated with the original topic and screenplay.

# 12. Analytics

The purpose of analytics is to determine what actually works.

Do not over-engineer analytics in version 1.

Track basic metrics.

## YouTube

* Views
* Likes
* Comments
* Average view duration
* Average percentage viewed
* Subscribers gained

## Instagram

* Views
* Likes
* Shares
* Saves
* Comments
* Followers gained
* Watch/retention metrics where available

## Experiment-Level Metrics

Most importantly:

* Number of videos
* Total views
* Average views/video
* Median views/video
* Engagement rate
* Followers/subscribers gained
* Generation cost
* Cost/video
* Revenue

# 13. 30-Day Experiment

## Week 1 — Build

Goal:

> Get the first video from topic selection to published Short/Reel.

Focus on:

* Topic Generator
* Researcher
* Script Generator
* Video generation
* YouTube upload
* Instagram upload

Manually inspect videos before publishing if necessary.

---

## Week 2 — Stabilize

Goal:

> Produce one acceptable video every day.

Identify:

* Bad topics
* Weak hooks
* Poor screenplay instructions
* Video-generation failures
* Unnatural voiceovers
* Poor visual quality

Fix the biggest problems only.

Do not start building unnecessary infrastructure.

---

## Week 3 — Experiment

Start varying:

* Topics
* Hooks
* Video length
* Story structure
* Visual styles
* Content angles
* Pacing

Begin identifying patterns in performance.

---

## Week 4 — Optimize

Use the first ~20–30 videos to determine:

* Which topics perform best?
* Which hooks perform best?
* Which video lengths perform best?
* Which storytelling formats perform best?
* Which visual styles perform best?
* Which platform performs better?
* Which content generates followers rather than just views?

Use those findings to influence future topic generation.

---

# 14. Long-Term Evolution

Only after the initial experiment shows potential should the system become more sophisticated.

Possible future architecture:

```text
                 Analytics
                     ↓
             Performance Agent
                     ↓
             Pattern Detection
                     ↓
             Topic Generator
                     ↓
              Better Topics
                     ↓
               Better Videos
                     ↓
                  Analytics
                     ↺
```

Eventually the system can learn:

> **Which combinations of topic + hook + format + length + storytelling style produce the best results?**

This turns the pipeline into a self-improving content system.

---

# 15. Explicitly Out of Scope

For the first 30-day experiment, do NOT build:

* Kubernetes
* Microservices
* Complex databases
* Neo4j
* Vector databases
* RAG
* Complex agent memory
* Enterprise authentication
* Production-grade observability
* Advanced retry infrastructure
* Complex CI/CD
* Elaborate frontend
* Multi-agent frameworks everywhere
* Sophisticated recommendation systems

The system is an **experiment**, not a production SaaS platform.

---

# 16. Success Criteria

The experiment should answer four questions.

### 1. Can the pipeline consistently create acceptable videos?

If no:

Improve the content/video generation process.

### 2. Can the videos consistently attract viewers?

If no:

Change niche, topics, hooks, formats, or storytelling.

### 3. Can the audience grow?

If views exist but nobody follows/subscribes:

The content may be generating curiosity without building an audience.

### 4. Can the economics work?

Compare:

```text
Revenue
  -
API / generation costs
  =
Potential profit
```

The ultimate goal is not:

> "I generated 50 videos."

It is:

> **"I found a repeatable content format that can potentially make money."**

---

# 17. Final Principle

The project should follow this philosophy:

> **Build the smallest system capable of running the experiment.**

Do not optimize the architecture before proving the business model.

First:

**Generate → Publish → Measure → Learn**

Then:

**Improve → Automate → Scale**
