# AI-Powered YouTube Shorts & Instagram Reels Generation Pipeline

## 1. Project Overview

Build an automated AI-powered short-form video generation system that creates vertical videos under 30 seconds for YouTube Shorts and Instagram Reels, targeting about 26 seconds to leave room for natural narration timing.

The system will use an image-to-motion approach instead of computationally expensive local AI video-generation models.

The objective is to automate the entire process:

1. Accept a structured screenplay generated using OpenAI API.
2. Generate AI images for individual scenes.
3. Animate the images using camera movements.
4. Generate voiceovers.
5. Generate and synchronize captions.
6. Add background music and sound effects.
7. Assemble everything into a final vertical video.
8. Prepare the video for automated publishing.

This is a 30-day content creation experiment, initially targeting one video per day.

Prioritize simplicity, reliability, modularity, low operational costs, and ease of iteration over enterprise-level complexity.

- Prefer lightweight local processing wherever possible.

## 3. AI Model and Provider Strategy

### LLM Provider: OpenAI API

Use the official OpenAI Python SDK to interact with OpenAI models.

OpenAI API will be responsible for LLM-based tasks such as:

- Processing screenplay-related instructions when required.
- Generating structured outputs where applicable.
- Handling future AI-assisted metadata generation.
- Supporting additional AI workflows as the project evolves.

Important implementation requirements:

- Use the official `openai` Python package.
- Store the API key in environment variables.
- Never hardcode API credentials.
- Keep model names configurable.
- Use structured outputs or JSON Schema where supported.
- Validate every model-generated response before passing it to another pipeline stage.
- Implement retry handling for transient API errors.
- Handle rate limits and token limits.
- Log API usage and errors without exposing sensitive credentials.
- Do not make unnecessary LLM calls during video assembly.

Example configuration:

```env
OPENAI_API_KEY=
OPENAI_MODEL=
```

Use the configured model rather than hardcoding a model name throughout the application.

### Image Generation Provider

Create a separate image-generation provider interface.

The implementation should support cloud-based image generation and allow OpenAI image-generation models or other providers to be integrated.

Requirements:

- Keep image generation independent of the LLM provider implementation.
- Generate images using screenplay-provided image prompts.
- Maintain consistent visual style across scenes.
- Support regeneration of individual failed images.
- Cache successfully generated images.
- Make model names, image quality and image dimensions configurable.
- Track API usage and estimated costs.

Do not assume image generation is free.

### Voice Generation Provider

Use a local TTS engine initially to minimize recurring API expenses.

Create a provider interface so cloud-based TTS can be integrated later.

### Transcription Provider

Use Whisper for speech transcription and caption generation.

Prefer a lightweight local implementation if it performs adequately on the available hardware.

## 4. Proposed Architecture

### Stage 1: Screenplay Input

The application receives a structured screenplay in JSON format.

The screenplay is generated by a separate AI agent using OpenAI API. The video-generation application should consume this JSON rather than regenerate the screenplay.

Example:

```json
{
  "video_title": "The Mystery of the Lost City",
  "target_duration": 30,
  "aspect_ratio": "9:16",
  "scenes": [
    {
      "scene_id": 1,
      "duration": 3,
      "voiceover": "Something strange happened thousands of years ago.",
      "image_prompt": "A mysterious ancient city buried beneath desert sand, cinematic lighting.",
      "motion": "slow_zoom_in",
      "on_screen_text": "A LOST CITY",
      "sound_effect": "dramatic_impact",
      "transition": "fade"
    }
  ],
  "background_music": {
    "mood": "mysterious",
    "volume": 0.15
  }
}
```

Requirements:

- Validate incoming JSON.
- Validate required fields.
- Ensure scene durations are positive.
- Ensure all scenes have image prompts and voiceover text.
- Generate a unique working directory for each video.
- Store the original screenplay for reproducibility.

### Stage 2: AI Image Generation

Generate one image per scene (four or five detailed photorealistic images per video) using a configurable provider. Use rich, consistent documentary-style compositions designed for slow zooms and pans rather than generating a separate image for every sentence.

Requirements:

- Create an abstract image-generation provider interface.
- Support OpenAI image generation as a provider.
- Allow additional providers without modifying the rest of the pipeline.
- Generate images suitable for vertical videos.
- Target 9:16 aspect ratio.
- Maintain consistent visual style across scenes.
- Save generated images locally.
- Allow regeneration of individual failed images.
- Implement retries and configurable rate limits.
- Cache successful images to avoid unnecessary API calls.

Naming convention:

```text
scene_001.png
scene_002.png
scene_003.png
```

### Stage 3: Image Animation

Use FFmpeg to convert static images into short animated video clips.

Implement:

- slow_zoom_in
- slow_zoom_out
- pan_left
- pan_right
- pan_up
- pan_down
- subtle_zoom
- static

Use FFmpeg filters such as `zoompan`.

Requirements:

- Each scene must produce a clip matching its screenplay duration.
- Output resolution: 1080 × 1920.
- Frame rate: 30 FPS.
- Pixel format: yuv420p.
- Handle images with different aspect ratios through cropping or padding.
- Ensure consistent dimensions and encoding.
- Avoid excessive memory consumption.

### Stage 4: Voiceover Generation

Generate narration using a local text-to-speech engine.

Requirements:

- Create a configurable TTS provider interface.
- Generate one voiceover audio file per scene initially.
- Maintain consistent voice settings.
- Save intermediate audio in WAV format.
- Normalize audio levels.
- Handle empty or invalid narration gracefully.
- Do not aggressively speed up narration to fit scene durations.
- Implement an audio synchronization strategy that preserves natural speech.

### Stage 5: Caption Generation

Use Whisper for speech transcription and caption timing.

Requirements:

- Generate subtitles from final narration.
- Use word-level timestamps where supported.
- Synchronize captions with the final video timeline.
- Support SRT and ASS formats.
- Use readable typography suitable for mobile viewing.
- Position captions within safe areas.
- Highlight important words where practical.

Support screenplay-provided on-screen text separately from spoken captions.

### Stage 6: Background Music and Sound Effects

Requirements:

- Select music based on the screenplay's requested mood.
- Use commercially licensed or appropriately royalty-free audio.
- Support configurable music directories.
- Implement background music volume control.
- Keep narration clearly audible.
- Apply audio ducking during narration.
- Support scene-specific sound effects.
- Apply smooth audio fades.
- Handle missing music or sound effects without crashing.

### Stage 7: Final Video Assembly

Use FFmpeg to combine scene clips, narration, captions, music and sound effects.

Requirements:

- Maintain scene order.
- Apply screenplay-defined transitions.
- Synchronize all audio and visual elements.
- Normalize final audio.
- Export a high-quality MP4.

Final specifications:

| Property | Value |
|---|---|
| Resolution | 1080 × 1920 |
| Aspect ratio | 9:16 |
| Frame rate | 30 FPS |
| Video codec | H.264 |
| Audio codec | AAC |
| Container | MP4 |
| Pixel format | yuv420p |

## 6. Pipeline Orchestration

Create a central orchestrator that executes each stage sequentially.

```text
Screenplay JSON
      |
      v
Validate Input
      |
      v
Generate Scene Images
      |
      v
Animate Images
      |
      v
Generate Voiceovers
      |
      v
Create Captions
      |
      v
Add Music and SFX
      |
      v
Assemble Final Video
      |
      v
Validate Output
      |
      v
Final MP4
```

Requirements:

- Track the status of every stage.
- Log execution details.
- Handle failures gracefully.
- Retry transient API failures.
- Resume from the last successfully completed stage.
- Avoid unnecessary asset regeneration.
- Support processing one screenplay JSON file through a single command.
- Retain intermediate assets for debugging.
- Provide an option to clean up temporary files.

## 13. Definition of Success

The initial version is successful when I can provide a valid screenplay JSON file and execute one command to generate a complete vertical video, preferably under 30 seconds, using four or five detailed scene images and natural narration. A longer runtime is acceptable when needed for a clear, complete story; never rush or cut off the narration to force a hard time limit.

The video must contain:

- AI-generated scene images.
- Smooth camera movement.
- Natural voiceover.
- Synchronized captions.
- Background music.
- Appropriate transitions.
- Correct 9:16 formatting.

The system should produce a final MP4 without requiring manual video editing.

**Primary objective: Build a reliable, affordable, repeatable content-generation pipeline capable of producing one short-form video per day for a 30-day experiment.**
